# وب‌سایت و پنل مدیریت مرکز ترک اعتیاد طلوع خورشید

یک سامانه کامل فارسی و راست‌به‌چپ برای معرفی مرکز بازتوانی، دریافت محرمانه درخواست مشاوره و مدیریت محتوای سایت و فرایند پیگیری مراجعان.

> نام مرکز، سال تأسیس، شماره ثبت و شماره تماس بر اساس اطلاعات تأییدشده کارفرما و صفحه رسمی اینستاگرام درج شده‌اند. نشانی دقیق، مجوزهای قابل نمایش عمومی و متن نهایی سیاست حریم خصوصی باید پیش از بهره‌برداری عمومی توسط مسئول مرکز تأیید شوند.

## امکانات

### سایت عمومی

- طراحی کاملاً واکنش‌گرا برای موبایل، تبلت و دسکتاپ
- رابط فارسی RTL با فونت محلی Vazirmatn و رعایت دسترس‌پذیری
- معرفی خدمات، مسیر درمان، فضای مرکز، پرسش‌های متداول و دعوت به تماس
- فرم درخواست مشاوره با اعتبارسنجی، محدودسازی نرخ و فیلد ضدربات
- ثبت مستقیم درخواست‌ها در PostgreSQL
- محتوای قابل ویرایش از پنل مدیریت
- گالری عمومی تصاویر و ویدیوهای فعالیت مرکز و روایت‌های بهبودی
- نمایش محتوای منتخب صفحه رسمی اینستاگرام مرکز به‌صورت فایل محلی پایدار و سریع
- تصاویر تحریریه‌ای اختصاصی و بهینه‌شده WebP با برچسب روشن «تصویر مفهومی»
- متادیتای SEO، رنگ مرورگر و صفحه سلامت سرویس

### پنل مدیریت

- ورود امن با گذرواژه هش‌شده و نشست HttpOnly هشت‌ساعته
- داشبورد آماری و نمایش آخرین درخواست‌ها و تغییرات
- جست‌وجو و پیگیری درخواست‌های مشاوره
- تغییر وضعیت درخواست: جدید، تماس‌گرفته‌شده، نوبت، بسته و بایگانی
- ثبت یادداشت داخلی برای هر درخواست
- مدیریت متن‌های صفحه اصلی
- بارگذاری، پیش‌نمایش، مرتب‌سازی، انتشار و حذف تصاویر و ویدیوها
- الزام ثبت رضایت آگاهانه پیش از انتشار عمومی روایت‌های بهبودی
- ایجاد، ویرایش، مرتب‌سازی، فعال/غیرفعال‌کردن و حذف خدمات
- ایجاد، ویرایش، مرتب‌سازی، فعال/غیرفعال‌کردن و حذف FAQ
- مدیریت کاربران مدیر و ویرایشگر
- مدیریت اطلاعات تماس و پیام اضطراری
- ثبت رویدادهای مهم در Audit Log

## فناوری‌ها

- Next.js 16، React 19 و TypeScript
- Tailwind CSS 4
- PostgreSQL 17
- Prisma ORM 6
- احراز هویت اختصاصی مبتنی بر JWT امضاشده، `jose` و `bcryptjs`
- Docker Compose برای اجرای تکرارپذیر در توسعه و تولید

## معماری

```text

  ├── سایت عمومی / فرم مشاوره
  └── پنل مدیریت /admin
             │
             ▼
      Next.js App Router
        ├── Server Components
        ├── Route Handlers /api
        ├── اعتبارسنجی Zod
        └── احراز هویت JWT
             │
             ▼

```

## شروع سریع با Docker

پیش‌نیاز: Docker و Docker Compose.

```bash
cp .env.production.example .env
# مقادیر محرمانه .env را تغییر دهید
docker compose up -d --build
docker compose ps
curl http://localhost:8012/api/health
```

سایت روی `http://localhost:8012` و ورود پنل روی `http://localhost:8012/admin/login` در دسترس است. ایمیل و گذرواژه اولیه از `ADMIN_EMAIL` و `ADMIN_PASSWORD` در `.env` خوانده می‌شوند.

## شروع توسعه بدون Docker برای اپلیکیشن

یک PostgreSQL در دسترس لازم است:

```bash
npm ci
cp .env.example .env
npm run db:generate
npm run db:push
npm run db:seed
npm run dev
```

جزئیات کامل در [development.md](./development.md) و راهنمای استقرار و پشتیبانی در [deployment.md](./deployment.md) آمده است.

## دستورات پروژه

| دستور | توضیح |
| --- | --- |
| `npm run dev` | اجرای توسعه |
| `npm run build` | ساخت نسخه تولید |
| `npm start` | اجرای نسخه ساخته‌شده |
| `npm run lint` | بررسی ESLint |
| `npm run typecheck` | بررسی TypeScript |
| `npm run db:generate` | تولید Prisma Client |
| `npm run db:push` | همگام‌سازی مدل دیتابیس |
| `npm run db:seed` | ایجاد داده پایه و مدیر اولیه، بدون بازنویسی محتوای ویرایش‌شده |

برای اعمال دوباره نسخه مرجع محتوا به‌صورت کنترل‌شده، `FORCE_CONTENT_SEED=true npm run db:seed` را اجرا کنید. این دستور متن خدمات، پرسش‌ها و محتوای اصلی را بازنویسی می‌کند؛ پیش از اجرای آن روی محیط واقعی نسخه پشتیبان بگیرید.

## امنیت و حریم خصوصی

- فایل `.env` نباید Commit شود؛ الگوهای امن در `.env.example` قرار دارند.
- در محیط اینترنت عمومی حتماً HTTPS، فایروال، محدودسازی دسترسی SSH و پشتیبان‌گیری رمزگذاری‌شده فعال شود.
- این پروژه داده‌های حساس مرتبط با سلامت دریافت می‌کند. پیش از استفاده واقعی، الزامات قانونی نگهداری داده، رضایت کاربر، مدت نگهداری و دسترسی کارکنان باید توسط مسئول حقوقی مرکز تأیید شود.
- نام، تصویر، صدا یا تجربه درمان افراد فقط با رضایت آگاهانه، قابل اثبات و قابل پس‌گرفتن منتشر شود. مدرک رضایت باید مطابق قوانین محل فعالیت نگهداری شود.
- هیچ گذرواژه یا کلید تولیدی داخل مخزن قرار نگرفته است.
- اطلاعات پراکسی یا حساب اینستاگرام هرگز در کد، دیتابیس یا فایل‌های رسانه ذخیره نمی‌شود. محتوای واردشده باید متعلق به مرکز یا دارای مجوز انتشار باشد.
- تصاویر مفهومی نباید به‌عنوان عکس واقعی ساختمان، کارکنان یا مراجعان معرفی شوند. عکس‌ها و ویدیوهای واقعی مرکز فقط در بخش رسانه‌ها و همراه با منبع نمایش داده می‌شوند.

## ساختار پوشه‌ها

```text

src/components/          اجزای رابط عمومی و پنل
src/lib/                 دیتابیس، احراز هویت و اعتبارسنجی
uploads/                 فایل‌های بارگذاری‌شده در توسعه؛ خارج از Git
prisma/schema.prisma     مدل داده
scripts/seed.ts          داده‌های پایه و مدیر اولیه
public/images/           تصاویر تولیدی سایت
docs/design/             مرجع بصری طراحی
Dockerfile               ایمیج اپلیکیشن
docker-compose.yml       اپلیکیشن و PostgreSQL
```
